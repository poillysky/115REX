## 文档分层

```
00 产品定位与整体架构
   ├─ 08 全栈框架（技术栈 · 仓库结构 · 不变量 · 路线）
   ├─ 05 资源整合搜索
   ├─ 06 Python 后端
   ├─ 07 接口契约          ← 客户端与后端的唯一事实源
   └─ 04 App 架构
        ├─ 01 iOS 硬规则（App 端）
        └─ 02 设计语言（两端共用 Token 与语义）
              ├─ 03 Web 端规范（Web 端特有）
              └─ 09 品牌资产（资产文件与规格）
```

01 与 02 的分工：**换掉品牌视觉后规则仍成立的写进 01，只有具体取值属于 02。**
02 的 Token 是两端共用的单一来源，03 只在其上补 Web 端特有的布局与交互；
02 只管「长什么样」，09 只管「资产文件怎么产出」。

## 写作约定

- 一篇文档只解决一个问题；出现第二个主题就拆出去。
- 表格优先于长段落；能写成检查清单的不写成散文。
- **文档与代码冲突时，以文档为准：改代码，不改文档。** 文档是「应该怎样」的规定，不是现状记录。
- 未定的事写进该篇的「未决项」，不要在正文里编一个答案。
- 尚未实现的设计留空即可，**不要**写成「当前状态：已实现」—— 状态会过期，规定不会。
- 视觉取值只写一处（02），其它篇用链接引用，不复述色值。

# 06 · Python 后端架构

> 唯一重点：**后端怎么组织、数据怎么存、任务怎么跑、Windows 上怎么跑起来。**
> 不涉及：产品定位（[00](00-product-architecture.md)）、provider 抽象（[05](05-resource-search.md)）、
> 接口字段（[07](07-api-contract.md)）、客户端分层（[04](04-app-architecture.md)）。
>
> **本篇是骨架**：定模块边界与运行形态，不定表结构与字段级实现。
> 技术栈：**Python + FastAPI + SQLite**，部署在用户自己的 Windows 机器上。

---

## 1. 技术选型

| 项 | 选择 | 理由 | 推翻条件 |
| --- | --- | --- | --- |
| Web 框架 | FastAPI | 自动 OpenAPI、异步原生（并发搜多源必需） | —— |
| 存储 | SQLite（WAL） | Windows 单机零依赖；查询模式简单 | 并发写入成瓶颈 → 迁 PG，仓储层已隔离 |
| ORM | SQLAlchemy | 换 PG 只改连接串 | —— |
| 校验 | Pydantic | FastAPI 自带，请求响应模型即契约 | —— |
| HTTP | httpx | 原生 async、超时可控 | —— |
| 媒体探测 | ffprobe | 唯一可靠的容器/编码探测 | 无 ffprobe 时降级为文件名解析 |
| 任务 | 进程内队列 + 单 worker（首版） | 规模小，不引入 Celery/Redis | 任务量超单机承受 → 拆独立 worker |

**不引入**：Celery、Redis、Docker、额外 ORM 框架。

## 2. 模块划分

| 模块 | 职责 | 禁止 |
| --- | --- | --- |
| `api/` | 路由、请求响应模型、依赖注入 | 直接碰数据库、直接调 provider |
| `services/` | 业务编排（搜索、动作、影视库、刮削、播放签发） | 依赖 FastAPI 的请求对象 |
| `providers/` | 资源源适配层 | 互相 import 彼此的 provider |
| `integrations/` | 外部系统（115、元数据源） | 反向依赖 `services/` |
| `storage/` | 引擎、模型、迁移 | 写业务逻辑 |
| `tasks/` | 队列与任务处理器 | 直接写数据库 |

**分层规则**：上层可以调下层，下层不能回调上层。`api` 层不得出现 SQL，
`services` 层不得出现 `Depends` / `Request`。

## 3. 数据模型（只列实体，不定字段）

| 实体 | 用途 | 关键点 |
| --- | --- | --- |
| 用户 / 设备 | 账号与设备绑定 | 设备级令牌吊销 |
| 令牌 | access / refresh，refresh 滚动 + 重放检测 | 服务端只存哈希 |
| 网盘绑定 | 115 账号（凭据加密） | 凭据只在 `integrations/115` 解密 |
| 影视条目 | 刮削后的作品条目 + 播放进度 + 收藏 | 账号级；幂等键 = 绑定 + 远端路径 |
| 字幕 / 音轨 | 外挂字幕、内封流索引 | 媒体探测后填充 |
| 资源动作 | 转存等异步任务的状态 | 状态持久化，进程重启可恢复为「已中断」 |
| 偏好 | 默认转存目录、默认字幕语言、启用的资源源、基础设定、代理、API 令牌 | 用户级，一账号一行；嵌套结构（图标库 / 基础 / 代理 / GitHub / 高级 / 插件）按 JSON 文本存，进程重启后仍生效 |

**索引策略**：只按实际查询模式建（按用户 + 标题 / 按用户 + 最近播放 / 令牌哈希）。
影视库搜索量级小，**不上全文索引**。

## 4. 115 集成

| 能力 | 用途 | 备注 |
| --- | --- | --- |
| 列目录 | 浏览网盘、定位已转存文件 | 同步影视库 |
| 探测 | ffprobe 探测容器、时长、编码、音轨、字幕流 | 结果缓存 |
| 转存 | 发起并轮询转存任务 | 长任务，见 §6 |
| 解析直链 | 生成可播放地址 + 必需请求头 | **当前未实现** |

**直链签发**：播放信息接口内部完成「探测 → 解析 → 返回」，返回给客户端的只有地址、
请求头、有效期。**115 Cookie / 账号信息一律不外传。**

**扫码登录**：走 115 开放平台的设备码流程（PKCE），四步 ——
申请设备码 → 查扫码状态 → 设备码换令牌 → 刷新令牌。
服务端只把二维码**内容**下发给前端；`code_verifier`、`access_token`、`refresh_token`
全程留在服务端，访问令牌到期前自动刷新。协议细节见 [07](07-api-contract.md) §2.2。

## 5. 入库与刮削

转存或下载完成后走一条入库流水线：

1. **探测** —— 容器、时长、分辨率、编码、音轨、内封字幕流。
2. **文件名解析** —— 作为元数据兜底，也是刮削的输入。
3. **元数据刮削** —— 外部源匹配标题与年份，写入标题、简介、海报、年份。
4. **字幕补全** —— 内封字幕 + 可选外挂字幕。
5. **写入条目** —— 幂等：同一绑定 + 同一路径更新而非插入。

**刮削失败不阻塞入库**：标题不太对但能播，好过条目不出现。

## 6. 任务系统

| 队列 | 内容 | 优先级 | 特点 |
| --- | --- | --- | --- |
| 动作 | 转存 / 下载 / 推送 | 高 | 长任务，可取消，状态对外可见 |
| 探测 | 媒体探测 | 中 | 短任务 |
| 刮削 | 元数据匹配 | 低 | 可延后 |
| 维护 | 过期清理、索引重建 | 最低 | —— |

**SQLite 并发纪律**：WAL 模式、写入串行化、设置忙等待超时。读多写少是本项目的天然形态。

**115 频控**：客户端内置令牌桶（速率待实测）、探测结果缓存、仅对可重试错误做指数退避。

## 7. 鉴权与凭据

| 项 | 方案 |
| --- | --- |
| 令牌 | JWT，access 短 / refresh 长且滚动 |
| 服务端存储 | refresh token 只存哈希 |
| 设备绑定 | 令牌关联设备；登出吊销该设备全部 refresh |
| 重放检测 | 旧 refresh 被复用 → 吊销该设备全部令牌 |
| 密码 | argon2 |
| 115 凭据 | 加密存储，仅集成层可解密 |

**重放检测是硬要求**：客户端并发刷新会把设备踢下线。客户端侧单飞，服务端侧检测兜底。

## 8. 配置

全部配置走环境变量，本地 `.env` 不入库。必填项：签名密钥、凭据加密密钥。
可调项：令牌有效期、搜索预算、115 频控速率、静态资源目录、CORS 白名单。

115 扫码登录的应用 ID 走 `REX_U115_APP_ID`，是公开值不是机密；默认沿用 MoviePilot
那款已开启设备码授权的公开应用，开箱即可扫码。

**静态托管优先于 CORS**：Web 由后端同源提供，生产不需要 CORS。

## 9. Windows 部署

| 方式 | 适用 |
| --- | --- |
| 前台进程 | 开发（带热重载） |
| Windows 服务 / 计划任务 | 长期运行，开机自启 |
| 打包分发 | 面向用户（需一并带 ffprobe） |

**baseUrl 按端切换**：本机浏览器走 `127.0.0.1`，局域网 App 走内网 IP，
iOS 真机必须 HTTPS（ATS 限制）。

## 10. 日志与安全

- 脱敏：直链查询串、请求头、播放令牌、115 Cookie 一律不落日志。
- 错误码统一出口，与 [07 §3](07-api-contract.md) 的码表一一对应。
- 内部异常不外泄，500 只给通用文案，堆栈进日志。
- 所有外部 HTTP 调用必须有超时与重试上限。
- ffprobe 处理的文件名必须做路径校验，禁止 shell 拼接。

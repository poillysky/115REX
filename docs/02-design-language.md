# 02 · 全局 UI 设计语言规范

> 唯一重点：**115REX 应该具备什么气质、长什么样。** 这一篇是可贯穿全项目的
> Visual Design Language + Design System + Interaction Specification。
>
> **产品形态**：115 网盘影视终端 + 资源整合搜索。服务端（Python）跑在用户自己的机器上，
> 负责账号、索引、聚合搜索与播放信息签发；**Web 端与 App 端是并列的两个客户端**，
> 共同面向使用者（见 [00](00-product-architecture.md)）。
>
> **视觉方向**：蓝紫渐变 + 大圆角 + 卡片化 + 双色图标体系，取自项目设计海报
> （资产与 Logo 打磨见 [09](09-brand-assets.md)）。**海报是视觉基准**：色值、圆角档位、
> 图标双轨、页面气质的最终依据是海报，不是任何外部产品。
>
> **本文是两端共用的设计语言**：Token、语义色、间距、圆角、排版、组件语义单一来源。
> App 端的系统层硬规则在 [01](01-ios-essentials.md)，Web 端特有的布局与交互在 [03](03-web-frontend.md)。
>
> 「不做就一眼安卓」的系统层硬规则（滚动、转场、禁用 Material、本地化、安全区、
> 状态栏回顶、表单语义、长按预览）在 [01](01-ios-essentials.md)，本文**不重复**，只给链接。
>
> 性质：**规定方向。** 本文是目标设计语言，不是现状记录。**代码与本文冲突时，
> 以本文为准，改代码不改文档**；所有条目都是「应该这样」，没有「可演进」的例外。
> 要改一条，走 §16 的变更流程。

## 1. 先定义产品气质

整体方向：**清透、克制、有序、轻盈、精致**，底色偏冷白与浅蓝灰，品牌色以蓝紫渐变出现。

不是安卓式的功能堆叠，不是企业后台式的数据面板，也不是全屏液态玻璃 ——
而是以 iOS 原生体验为基础、带清晰品牌识别度的**影视工具**语言。

### 1.1 五个设计支柱

| 支柱 | 含义 | 反例 |
| --- | --- | --- |
| **清透 Clarity** | 浅冷底色、白色卡片、清晰边界、克制装饰。界面轻盈，不沉重不拥挤 | 深灰底 + 密集描边，一眼后台 |
| **渐变 Gradient** | 品牌蓝紫渐变只出现在**品牌位**：Logo、启动页、主按钮、功能图标底板、播放页主控 | 每个卡片、每行列表都加渐变 |
| **秩序 Consistency** | 色彩、排版、间距、圆角、图标、交互状态、组件规则全站共享 | 每个页面各有一套圆角 |
| **原生 Native** | 导航、手势、键盘、安全区、弹窗、滚动、触控反馈遵循 iOS 习惯 | 长得像 iOS，但侧滑返回失效 |
| **精致 Refinement** | 精确对齐、字体基线、图标比例、材质、微动效与细节反馈 | 靠大量装饰掩盖对不齐 |

### 1.2 风格边界

| 应该使用 | 应该避免 |
| --- | --- |
| 浅冷底色 + 纯白卡片、统一大圆角、极低对比边界 | 全屏毛玻璃、所有卡片都带重阴影、无节制渐变 |
| 品牌渐变只做强调；双色图标体系（功能图标蓝底、操作图标线性） | 霓虹光效、五颜六色的图标混搭、每个图标一个渐变 |
| 细腻图标、清晰排版、适度留白、局部玻璃效果 | 密集描边、每页一套设计语言、把渐变当装饰铺满 |

**最重要的一条约束：海报给的是「色调与规格」，不是「每个页面都做成海报」。**
列表页、登录页、详情页、播放器必须共享视觉基因（同一套 Token、同一套图标、同一套动效），
但保留各自合理的布局与信息密度。统一的是**语言**，不是**版式**。

## 2. 全局视觉风格

| 维度 | 统一规范 |
| --- | --- |
| 产品气质 | 现代、清透、轻盈、可信赖 |
| 平台基调 | iOS 原生交互 + 现代移动端布局 |
| 基础背景 | 冷白 `#F3F4F6` / 纯白 / 局部浅蓝渐变 |
| 品牌强调 | 品牌蓝 `#176BFF`，强调场景用蓝紫渐变 |
| 内容容器 | 大圆角（16–22）、极低对比边界、适量留白、卡片化 |
| 图标 | 双轨：功能入口图标（蓝底渐变 + 白色字形）/ 系统操作图标（线性） |
| 材质 | **实色表面为主，玻璃为辅**（见 §6） |
| 阴影 | 轻、软、低对比，**只用于必要的浮层** |
| 排版 | 层级明确、对齐稳定、辅助信息弱化、标题负字距 |
| 动效 | 短、顺滑、自然、有明确交互意义 |
| 信息密度 | 按页面职责分级控制，不强行统一（见 §4.3） |
| 装饰原则 | 功能优先，渐变只在品牌位 |

## 3. 色彩系统

颜色不是「挑几个好看的值」，而是**角色体系**。页面与组件按角色取色，
不允许在业务文件里随手写色值。

### 3.1 基础色板

取值依据：**主色与品牌色取自设计海报，语义色取自已验过对比度的调深版本**
（海报里的 `#F59E0B` / `#EF4444` 为通用 Tailwind 值，在白底上对比度不足，不采用）。

| Token | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| `background` | `#F3F4F6` | `#000000` | 页面底色 |
| `surface` | `#FFFFFF` | `#1C1C1E` | 卡片、弹窗、输入面板 |
| `surfaceSecondary` | `#F6F7F9` | `#2C2C2E` | 次级卡片、分组内的信息块、行按压态 |
| `primary` | `#176BFF` | `#3D8BFF` | 主按钮、选中态、进度 |
| `primarySubtle` | `#E0F2FE` | `#0E1B2E` | 淡蓝底、轻量高亮、氛围渐变起点 |
| `brandViolet` | `#8B5CF6` | `#A57BFF` | 品牌紫，仅用于渐变终点与少量强调 |
| `textPrimary` | `#171A22` | `#F5F5F7` | 标题、主正文 |
| `textSecondary` | `#6B7280` | `#98989D` | 日期、说明、路径 |
| `textTertiary` | `#6E757F` | `#8E8E93` | 占位符、说明备注、空态图标 |
| `separator` | `#E5E8EE` | `#38383A` | 分隔线、轻边界 |
| `success` | `#16845B` | `#2FBF85` | 成功、完成 |
| `warning` | `#B96B08` | `#E8A030` | 警告、部分结果、降级 |
| `danger` | `#D83B45` | `#FF5F63` | 错误、破坏性操作 |

> **语义色刻意比品牌色暗一档**：状态色要能被读到，不能和品牌蓝抢注意力。
> 深色列的红绿黄必须重新调亮，不能沿用浅色值。

> **文字三阶必须过 4.5:1（2026-10 调整）**：先前 `textSecondary` `#7D8594`（白底约 3.5:1）、
> `textTertiary` `#B8BCC4`（约 1.9:1）只够做装饰，一旦承载日期、说明、提示就读不清。
> 现浅色改为 `#6B7280`（约 4.7:1）/ `#6E757F`（约 4.6:1），两者亮度接近、层级靠位置与字号区分；
> 深色 `textTertiary` 提到 `#8E8E93`（深底约 4.8:1）。禁用态**不再**靠降低文字色亮度表达，
> 改用中性底 + `textSecondary`（见 §10）。

### 3.1.1 品牌渐变

品牌渐变是**唯一允许的渐变**，只出现在品牌位：

| 名称 | 停靠点 | 用途 |
| --- | --- | --- |
| `brandGradient` | `#25C4FF` → `#168BFF` → `#315BFF` → `#8B35F6`（约 0°→45°） | Logo、启动页、功能图标底板、播放页主控 |
| `brandGradientSoft` | `primarySubtle` → `surface` 的极低对比过渡 | 登录背景、首页顶部氛围 |

规则：

- 渐变**不做文字底**（除非叠白色文字且已实测对比度 ≥ 4.5:1）。
- 同一个视图内**最多一处**出现 `brandGradient`；第二处必须是 `brandGradientSoft`。
- 渐变方向统一 45° 左上到右下，不逐页变化。
- **Web 端内页不铺渐变**：空状态底、海报兜底、头像底、进度条一律用中性面（`surfaceSecondary`）
  或单色 `primary`。渐变留在品牌位，避免每个卡片都带一层"AI 味"的彩色氛围。

### 3.2 角色使用规则

| 角色 | 使用范围 | 约束 |
| --- | --- | --- |
| `primary` | 主按钮、选中文字与进度 | **不大面积铺满页面**；装饰性用色一律禁止 |
| `primarySubtle` | 淡蓝背景、轻量高亮 | 不承担主要文字对比；**不用作导航选中底**（选中态见 §9） |
| `brandViolet` | 渐变终点、少量强调标签 | **不单独用作按钮底色**，否则会与 `primary` 争主色 |
| `background` | 页面底色 | 干净、稳定，不随模块变化 |
| `surface` | 卡片、弹窗、输入面板 | 与 `background` 形成清晰层级 |
| `surfaceSecondary` | 次级卡片、信息分组 | 与 `surface` 保持**轻微**明度差 |
| `textPrimary` | 标题、主要内容 | 正文不用纯黑 `#000` |
| `textSecondary` | 日期、说明、路径 | 清晰但不抢焦点 |
| `separator` | 列表分隔、轻边界 | 低对比，**避免把页面切成一格一格的网格** |
| 状态色 | 成功 / 警告 / 错误 | 统一语义色 + 文字说明，不单靠颜色传达 |

### 3.3 渐变规范

- 渐变只在 §3.1.1 列出的两处使用；**不要**在每个按钮、卡片、列表行里分别加渐变。
- 不要让背景渐变干扰标题、状态栏或输入内容的可读性。
- 渐变服务于**品牌识别与空间氛围**，不能取代内容层级。

### 3.4 深色模式

深色模式是**独立定义的一套**，不是反相：

- 页面背景、卡片、次级表面分别定义（见 §3.1 深色列）。
- 品牌蓝必须针对深底重新验证可读性并提亮（`#176BFF` → `#3D8BFF`）。
- 品牌渐变在深色下降低整体亮度、提高紫端占比，避免浅蓝端过曝。
- 状态色必须提亮（见 §3.1 深色列），浅色值在深底上对比不足。
- 玻璃效果必须针对深色背景重新调参（模糊、透明度、边缘高光）。
- **禁止**用 `Color.invert` 或简单明度算子生成深色。

```dart
final c = AppPalette.of(context);
Container(color: c.surface);      // 对
Container(color: AppColors.surface); // 错：深色下不会变
```

取色入口固定为 `AppPalette.of(context)`（解析机制见 01 §8.8）。

## 4. 空间、布局与留白

### 4.1 布局原则

- 明确的页面边距与内容最大宽度；**内容不贴屏幕边缘**。
- 顶部导航、正文、底部导航**分别管理**，不互相挤占。
- 内容按重要程度形成自然的阅读顺序，靠**模块间距**而非大量边框区分区域。
- 图标、文字、辅助信息遵循统一对齐规则（左对齐基线一致，数字列右对齐）。
- 必须适配不同 iPhone 尺寸、安全区、动态字体与横屏。

### 4.2 间距体系（4dp 基准）

| Token | 值 | 用途 |
| --- | --- | --- |
| `space1` | 4 | 图标与文字微间距 |
| `space2` | 8 | 紧凑控件间距 |
| `space3` | 12 | 列表内部间距 |
| `space4` | 16 | 常规组件间距、**页面水平边距**、卡片内边距 |
| `space5` | 20 | 宽松页面水平边距、**卡片默认内边距** |
| `space6` | 24 | 卡片内部或模块间距 |
| `space8` | 32 | 大模块之间 |
| `space10` | 40 | 重点区域之间 |

- 是 **Token 而非硬性数值**：紧凑列表与宽松首页可以采用不同密度，但必须有设计依据。
- 页面左右边距在**同一页面内**固定（默认 16，低密度页面可用 20），不逐模块变化。
- 不在页面里写裸 `EdgeInsets.all(13)` 这类散值。

### 4.3 页面密度分级

| 密度 | 页面类型 | 设计要点 |
| --- | --- | --- |
| **高密度** | 搜索结果、候选列表、目录浏览、任务列表 | 扫描效率优先：整齐对齐、连续列表、行高稳定、辅助信息弱化 |
| **中密度** | 影视库首页、作品详情、资源源状态 | 分组卡片 + 海报网格，兼顾信息量与呼吸感 |
| **低密度** | 登录、首次启动、空状态、播放器待播 | 单一任务、大留白、清晰视觉焦点、可用品牌渐变 |

密度是**按页面职责**分配的，不是全局统一。但同一类页面在全站必须用同一档密度。

## 5. 几何、圆角与表面

### 5.1 圆角分级

**统一圆角 ≠ 所有控件同一个圆角。** 按组件面积、功能、层级分档（与海报一致）：

| Token | 值 | 使用位置 |
| --- | --- | --- |
| `radiusSm` | 8 | 小型标签、紧凑元素、徽章 |
| `radiusMd` | 12 | 小型容器、次级控件、图标底板 |
| `radiusLg` | 16 | 输入框、常规按钮 |
| `radiusXl` | 22 | 主要卡片、底部面板 |
| `radius2xl` | 28 | 大型主面板、App 图标底板、特殊展示区域 |
| `radiusFull` | 999 | 胶囊、圆形头像、开关 |

规则：

- **面积越大、圆角越大**，保持视觉比例一致（否则小控件显得钝、大卡片显得硬）。
- 图标底板圆角用**比例值** `size * 0.24`，不占档位（图标圆角本就随尺寸缩放）。
- 主按钮在 iOS 上优先用**胶囊**（`radiusFull`，即 `CupertinoButton.filled` 的形态）；
  需要方角时用 `radiusLg`，不要用 12 以下的小圆角 —— 会明显偏安卓。
- 不允许出现上表之外的圆角，也不允许写 `10` / `14` / `18` 这类散值。

### 5.2 表面层级

| 层 | 名称 | 用途 | 材质 |
| --- | --- | --- | --- |
| Level 0 | Background | 页面基础底色，提供整体环境 | 实色 + 可选氛围渐变 |
| Level 1 | Surface | 主要内容面板、分组容器、表单区域 | 实色 |
| Level 2 | Secondary Surface | 卡片内部的信息块、次级数据区域 | 实色（轻微明度差） |
| Level 3 | Overlay | 弹窗、菜单、浮动面板、悬浮工具栏 | 实色或玻璃（见 §6） |

**阴影只用于表达空间关系。** 普通卡片优先用背景差异与留白建立层级，
不要给每个容器加投影。Level 1 / Level 2 默认**无阴影**。

## 6. 材质：实面板、渐变与玻璃

这套语言的核心**不是全玻璃化**，而是不同材质各司其职。

### 6.1 三种材质

| 材质 | 用在哪 | 不用在哪 |
| --- | --- | --- |
| **实色** | 主体内容的默认材质：列表、表单、统计卡片、设置项、媒体信息、主要区域 | — |
| **渐变** | 首页顶部、品牌展示、登录背景、少量视觉重点 | 不成为每个组件的默认背景 |
| **玻璃** | 悬浮工具栏、媒体控制、顶部浮动搜索、轻量快捷操作、局部导航 | 不做全屏毛玻璃，不铺满整页 |

### 6.2 玻璃的硬门槛

玻璃必须有**真实内容供其模糊**，否则就是一层没有意义的半透明灰。

- 控制模糊半径、透明度、边缘高光，**叠加层编号不超过 2 层**。
- 保证文字与图标在任何背景内容上都清晰可读 —— 必要时加 scrim，而不是提高不透明度。
- 深色模式下玻璃必须重新调参，不能沿用浅色参数。
- 无内容可模糊时（纯色背景上的工具栏）**改用实色**。

### 6.3 高光与阴影

- 高光只用于少量特殊材质（图标底板、玻璃边缘），不作为通用装饰。
- 阴影柔和、低对比、**不产生明显黑边**。
- 普通内容卡片不应呈现「浮在屏幕上」的厚重效果。
- 禁止无节制使用内阴影、外发光、多层渐变。

## 7. 图标与视觉资产

必须建立**统一图标系统**，不能由每个页面自行挑选。系统层规则（语义键、44×44 热区、缺失字形处理）见 01 §6，本节只管**外观与双轨分工**。

### 7.1 双轨分工

海报确立了双色图标体系，两条轨**不能混用**：

| 轨 | 外观 | 用在哪 | 不用在哪 |
| --- | --- | --- | --- |
| **功能入口图标** | 圆角底板 + 品牌蓝底（可用 `brandGradient`）+ **白色**字形，底板圆角 `size * 0.24` | 首页功能宫格、影视分类入口、资源源入口 | 导航栏、工具栏、列表行尾部 |
| **系统操作图标** | **线性**单色字形，跟随文字色 | 返回、搜索、设置、更多、添加、排序、筛选、关闭、分享、删除、刷新 | 功能宫格 |

### 7.2 系统操作图标

- 统一使用 **Phosphor**（`packages/phosphor_flutter` fork），全站不混用其他图标库；
  SF 名称 → 字形的映射统一在 `apps/app/lib/core/icons/ios_icon.dart`。
- 线性态用 Regular，需要实心强调（播放键、已收藏）时用 Fill。同一语义的两种状态必须成对取自同一字形。
- **光学居中**，不只依赖数学中心。
- 统一常规尺寸（22~26）与热区（≥ 44×44）。
- 激活 / 禁用 / 选中状态采用统一规则（描边粗细或颜色变化，二选一，全站一致）。

### 7.3 功能入口图标

- 底板尺寸、圆角（`size * 0.24`）与整体比例统一，宫格间距固定。
- 底板可用品牌蓝或 `brandGradient`，字形**必须纯白**，不做双色字形。
- 允许一层**极轻**的上部高光（`#FFFFFF` 22% → 0）；不做内阴影与外发光。
- 图形简洁、易识别，缩小到 40 仍清晰。
- 不混用不同设计体系的素材；缺图标时按同一规格补，不放行临时图标。

### 7.4 插画与封面

插画、海报、媒体封面、功能图标是**不同类型的资产**，不强套同一处理：

- 海报与封面保留内容本身的色彩与比例，**不叠品牌色滤镜**。
- 空状态插画可用中性面（`surfaceSecondary`）作底，配线性图标，**不铺品牌渐变**，不能比主要操作更醒目。
- 图片的加载中 / 失败 / 缺失封面需要统一占位样式（同一套骨架灰、同一套失败图标）。
- 品牌资产（Logo、App 图标、字标）的规格与打磨方向见 [09](09-brand-assets.md)。

## 8. 字体与排版

层级靠**字号 + 字重 + 颜色的组合**建立，不靠随意放大加粗。字阶取自海报。

| Token | 字号 | 字重 | 用途 |
| --- | --- | --- | --- |
| `display` | 32 | Semibold | 品牌名、首屏重点（极少使用） |
| `heading1` | 30 | Bold | 页面主标题、登录页标题 |
| `heading2` | 22 | Semibold | 模块标题、大数值 |
| `heading3` | 18 | Medium | 卡片内小标题、分组标题 |
| `body` | 16 | Regular | 正文、输入内容、列表名称 |
| `label` | 15 | Medium | 按钮、标签、控件文字 |
| `caption` | 13 | Regular | 日期、路径、辅助信息、Tab 文字 |

规则：

- **使用系统字体，不指定 `fontFamily`**。iOS 自动用 SF Pro；写 `fontFamily: '-apple-system'`
  在 Flutter 里**不会命中 SF Pro**，只会回退（见 01 §5.1，有守门测试）。
- 标题档（`display` / `heading1` / `heading2`）使用**负字距**（约 -0.35 ~ -0.7），
  这是海报的排版特征；正文与辅助信息字距为 0。
- 统一行高、字重、段落间距与文本颜色；同一层级的行高全站一致。
- 主标题 / 正文 / 辅助信息的层级差必须稳定，不允许靠 `fontSize` 随手微调。
- 文件名、媒体标题、日期、容量需定义截断与换行策略（单行省略 / 两行截断 / 允许换行，逐类固定）。
- **不允许**重要内容因固定高度被裁切。
- 支持动态字体与辅助功能（钳制范围见 01 §5.3）。
- 数字、单位、日期、百分比、状态标签保持统一格式；时间码与统计数字用等宽数字。

文字取色：标题与主正文 → `textPrimary`；辅助描述 → `textSecondary`；占位 → `textTertiary`。
三阶**都**要过 4.5:1，弱化靠字号与位置，不靠把字调淡到读不清。
彩色底（品牌渐变或 `primary`）上的文字**只能**用白色，且必须实测对比度。

Web 端补充（docs/03 可执行细则以本节为准）：

- 字阶只此七档，**不新增 11 / 12px 档**；辅助信息一律 `caption`（13），更小的 `kbd` 提示也不低于 13。
- 分组类小标题（侧栏分区、设置分组）用 `caption` + 500 + `sentence case`，
  **不加字距、不加大写、不做 eyebrow**。
- 正文行宽收在 60–72 个西文等宽字符（约 `68ch`），超出用容器限宽而不是缩字号。

## 9. 导航系统

全 App 共享同一套导航语言。落地写法与转场细节见 01 §3、§9。
**本节以 App 端为准**；Web 端的导航形态与响应式规则见 [03](03-web-frontend.md)。

### 9.1 页面顶部

- 页面标题层级清晰（大标题 / 普通标题二选一，按页面类型固定）。
- 返回、关闭、右侧操作**位置稳定**，不随页面变化。
- 搜索页、详情页、沉浸式媒体页可使用不同导航结构，但**行为一致**（侧滑返回、状态栏处理一致）。
- 处理状态栏、灵动岛与滚动时的导航变化（收缩、透明、隐藏）。

### 9.2 底部 Tab Bar

- 图标与文字垂直排列，图标 24、文字用 `caption`。
- Tab 图标走**系统操作图标轨**（线性），**不使用**功能入口图标（蓝底底板）——底板在 24pt 尺寸下会糊成色块。
- 选中 `primary`，未选中 `textSecondary`（不用纯灰到几乎看不见）。
- **Web 侧栏**：选中态用中性灰 pill（`surfaceSecondary` 底 + `textPrimary` 文字），
  不使用品牌蓝底、不使用左侧色条；分区小标题用 `caption` + 500，不加字距。
- 背景与内容分离（系统磨砂），**不使用厚重阴影**。
- 充分处理底部安全区；**不遮挡**最后一条列表或底部主要操作（列表底部留出 Tab 高度）。
- 切换 Tab 保留各页状态与滚动位置。

### 9.3 页面转场

- 常规页面用自然的 iOS 层叠推入 + 侧滑返回。
- 模态任务用合适的弹出形式（sheet / 全屏模态），不用推入代替模态。
- 详情、播放器、沉浸式页面按场景调整导航可见性。
- **避免**无意义的整页缩放、旋转与复杂转场。

## 10. 组件体系

组件共享视觉 Token，但**允许通过明确的变体**适应场景。不要为了统一而让所有组件
拥有相同的形状、尺寸与密度 —— 那是另一种不一致。

| 组件 | 职责 | 关键约束 |
| --- | --- | --- |
| `AppScaffold` | 页面基础结构与安全区 | 顶部/底部安全区只在这里处理一次 |
| `AppNavigationBar` | 标题、返回、操作按钮 | 高度与字号固定，不逐页调 |
| `AppTabBar` | 底部全局导航 | 见 §9.2 |
| `AppButton` | 主 / 次 / 文字 / 图标按钮 | 主按钮胶囊；主操作单色 `primary`，次操作中性面；统一按压反馈与禁用态 |
| `AppTextField` | 输入、密码、搜索、校验 | 聚焦/错误/禁用三态完整；键盘行为见 01 §8 |
| `AppCard` | 主要卡片与次级信息面板 | Level 1 无阴影；内边距 `space4` |
| `AppListTile` | 列表行、辅助信息、尾部操作 | 行高稳定；点击热区整行；禁止 InkWell |
| `AppIconTile` | 功能入口图标 + 标签 | 底板比例与宫格间距固定 |
| `AppDialog` | 确认、警告、错误、信息 | 按钮文案为动词；破坏性操作标红 |
| `AppSheet` | 底部操作面板与选择器 | 拖动关闭；圆角 `radiusXl` |
| `AppToast` | 轻量操作反馈 | 不阻断操作；不与 Dialog 混用 |
| `AppLoading` | 局部加载、骨架屏、任务进度 | 用 `CupertinoActivityIndicator`；骨架尺寸与真实内容一致 |
| `AppEmptyState` | 空列表、无搜索结果、首次使用 | 插画弱于主操作，必须给下一步动作 |
| `AppErrorState` | 网络错误、权限不足、服务不可用 | 必须可重试，且说明原因 |
| `AppSegmentedControl` | 分段切换与过滤 | 位置固定，切换不跳动 |
| `AppGlassSurface` | 局部玻璃材质容器 | 必须满足 §6.2 的门槛 |
| `AppMediaArtwork` | 封面、占位图、加载状态 | 三种状态视觉统一 |
| `AppStatusBadge` | 状态标签、数量、轻提示 | 颜色只用语义色，不引入新色 |

**命名与现状的对应关系**：上表是**角色清单**，不强制类名。App 端采用 `Ios*` 前缀，
职责与上表一一对应，引用时按职责找，不按名字找。**本表以 App 端为准**；
Web 端的组件形态与实现待定，但语义与状态要求沿用同一套（见 [03](03-web-frontend.md)）：

| 角色 | App 端实现 |
| --- | --- |
| AppScaffold / AppNavigationBar | `CupertinoPageScaffold` + `CupertinoSliverNavigationBar`（不另包一层，见 01 §2） |
| AppTabBar | `CupertinoTabScaffold` / `CupertinoTabBar` |
| AppButton | `IosButton` |
| AppCard | `IosCard` |
| AppListTile | `IosInset` + `IosRowSeparator` |
| AppIconTile（功能入口图标） | `IosAppIcon` + `IosAppIconLabel` |
| AppEmptyState / AppLoading / AppErrorState | `IosEmptyState` / `IosLoading` / `IosErrorState` |
| 图标（系统操作类） | `IosIcon` |
| AppTextField / AppDialog / AppSheet / AppToast / AppSegmentedControl / AppGlassSurface / AppMediaArtwork / AppStatusBadge | 未封装，直接使用 Cupertino 原生组件；出现第二次重复实现时才抽组件 |

新增组件前先问：**能否用现有组件的变体表达？** 能就不新增。
新增时沿用 `Ios*` 前缀，并在本表登记角色对应。

**Web 端组件补充约束**（`apps/web/src/features/shell/components`）：

- 禁用态用中性底 + `textSecondary`，**不用 `opacity`**（半透明会把文字一起压到读不清）。
- 焦点只走 `:focus-visible` 统一焦点环，输入框不许 `outline: none` 后只换边色。
- 同一角色只留一份实现：系统设置类页面的分组卡 / 行 / 开关统一由 `SysStyles` 提供，
  页面里不再各写一套 `.card` / `.row` / `.switch`。

> **不引入 Material 组件。** 外部品牌素材（含旧品牌 kit）里的 `ThemeData` / `FilledButton` /
> `Card` / `CircularProgressIndicator` 一律不搬，只搬色值与尺寸语义，按 Cupertino 重写。
> 守门测试见 01 §4。

## 11. 页面类型设计规则

不同页面共享设计语言，同时保留各自功能逻辑。

| 页面类型 | 设计要点 |
| --- | --- |
| **影视库首页** | 继续观看置顶；海报网格按系列分组；功能入口用线性图标 + 文字，**不做彩色图标砖**；**控制模块数量**，避免堆叠 |
| **列表 / 搜索结果** | 阅读效率、对齐、密度优先；作品层用分组标题，候选层用连续列表；**不为每个候选加独立卡片**；降级资源源灰显并说明 |
| **详情页** | 主信息与辅助信息层级清楚；海报 + 元数据 + 候选列表分区；主操作（播放 / 转存）突出，次操作收进工具栏 |
| **表单 / 登录** | 低视觉噪声、大留白、单一路径；品牌渐变可用于背景；状态完整（校验、错误、加载）；键盘、焦点、提示、提交反馈必须实测 |
| **设置页** | 清晰分组、统一列表项、原生开关；说明文字弱于设置名称；高风险操作（解绑网盘）独立分组并二次确认 |
| **媒体播放器** | 以沉浸为核心；控件出现清晰、隐藏不干扰；玻璃只用于控制层；播放主控可用 `brandGradient` 作为唯一强调；进度/字幕/音轨/手势/锁定状态明确；**不套用普通页面卡片布局** |
| **资源源状态页** | 每个源一行：健康度、最近成功率、缓存时间；`partial` 的成因在此可解释；不使用红色大面积警示（降级不是错误） |

## 12. 动效与交互反馈

统一动效系统，不让每个组件各自定义动画。

- **微交互**：快、轻、即时（按压 120ms 量级）。
- **页面转场**：自然连贯，符合 iOS 导航习惯（200–400ms）。
- **弹窗与底部面板**：有明确的进入、退出与拖动反馈。
- **选中状态**：及时反映，不产生明显跳动。
- **加载过程**：按真实业务状态更新。
- **成功与失败**：明确、可理解、可恢复（提供下一步动作）。
- **列表更新**：避免突然重排与位置跳变（保持 key 稳定、必要时用动画过渡）。
- 支持系统「减少动态效果」偏好。

禁止：

- 所有控件同时弹跳。
- 持续播放无意义的循环动画。
- 用假进度条代替真实任务状态。
- 用复杂动画掩盖性能问题。
- 页面切换出现闪白、黑屏或内容错位。

动效 Token 统一入口，不在页面里写裸毫秒数。

## 13. 交互状态与异常状态

任何有交互能力的组件都必须定义完整状态：

`Default` · `Pressed` · `Focused` · `Selected` · `Disabled` · `Loading` · `Success` · `Error`

任何页面都必须考虑：`Empty` · `Loading` · `Error` · `Offline` · `Permission Denied`，
**不能只设计成功场景**。

反馈必须与真实业务状态一致。不得用静态按钮、假弹窗、点了没反应的控件制造「完成度」。

| 状态 | 视觉要求 |
| --- | --- |
| Loading | 局部用菊花 / 骨架，不用整页遮罩打断已加载内容 |
| Error | 说明原因 + 可重试动作，不用「出错了」这类空话 |
| Empty | 一句说明 + 一个主要动作，插画不抢焦点 |
| Offline | 区分「离线」与「服务不可用」，给不同的恢复路径 |
| Permission Denied | 说明需要什么权限、去哪开启 |

## 14. 工程实施要求

- App 端用 **Cupertino 组件**建立 iOS 交互基础（禁用清单见 01 §4）；Web 端沿用同一套 Token 与语义，组件按平台惯例选型。
- 建立统一的 Theme、Design Tokens 与可复用组件；业务页面**不直接散落**颜色、圆角、间距常量。
- **Token 唯一来源是 `packages/design-tokens/tokens.json`**，由 `tools/` 生成两端常量
  （App → `apps/app/lib/core/theme/`，Web → `apps/web/src/core/theme/`）。
  **不允许各端手写色值**，本节表格是 Token 的规范说明，不是第二份实现。
- 保持既有路由、状态管理、数据模型与业务逻辑；**不因 UI 优化擅自改架构**。
- 不引入没有明确价值的第三方依赖。
- 对图片、模糊、透明层与动画做性能控制（玻璃与阴影是主要开销）。
- 处理不同屏幕尺寸、安全区、动态字体、深色模式与键盘。
- 避免过度嵌套布局与不必要的重建。
- **用真实运行截图做视觉验收**，不以代码「看起来对」为准。

App 端目录与分层边界以 [04](04-app-architecture.md) 为准，Web 端规则以 [03](03-web-frontend.md) 为准，
仓库结构以 [08 §2](08-fullstack-framework.md) 为准；本文只规定 UI 层怎么组织。

## 15. 落地顺序与验收

### 15.1 四步落地（避免只学会模仿颜色和圆角）

| 步骤 | 做什么 | 完成标志 |
| --- | --- | --- |
| 1 | **建立 Token**：颜色（含品牌渐变）、字体、间距、圆角、图标、动效 | `tokens.json` 唯一，两端生成物一致，业务文件无裸值 |
| 2 | **建立基础组件**：按钮、输入框、列表项、卡片、导航、弹窗、功能图标底板 | 组件状态完整，不含业务 |
| 3 | **做代表性页面**：影视库首页 / 搜索结果 / 播放器选其一 | 整页符合本文，含深色模式 |
| 4 | **截图验收并推广** | 截图逐项校对通过，再套用到其余页面 |

### 15.2 Agent 执行流程

1. 先读 [00](00-product-architecture.md)、本文、[01](01-ios-essentials.md)、[03](03-web-frontend.md)（Web 端）与现有路由和状态管理实现。
2. 分析参考图的色彩、结构、比例、组件、信息层级 —— 分析**原则**，不照抄版式。
3. 确认 Token，复用既有组件；缺组件先补组件，不在页面里就地拼。
4. 选一个代表性页面完成第一轮实现。
5. 在目标设备尺寸下**实际运行并截图**。
6. 按截图检查布局比例、对齐、间距、字体、图标、颜色、材质。
7. 修正偏差，再把已验证规范推广到其他页面。
8. 检查真实交互、异常状态、键盘、安全区、滚动行为。
9. 跑分析、测试与必要性能检查，确认没破坏原有业务逻辑。

**遇到设计不明确处：优先遵循现有 Token、已验收页面、既有组件；不得擅自发明新视觉风格。**
确实需要新增时，走 §16。

### 15.3 最终验收标准

- [ ] 整个 App 一眼看上去属于**同一个产品**
- [ ] 页面风格统一，但不同页面保留合理的信息密度
- [ ] 颜色、字体、间距、圆角、图标、材质都有明确规则可循
- [ ] 视觉层级清楚：重要信息突出，辅助信息克制
- [ ] 玻璃效果适量且可读性良好
- [ ] 无错位、溢出、遮挡、突兀跳动
- [ ] 所有按钮与交互控件有真实功能及完整反馈
- [ ] 不同屏幕尺寸下布局稳定
- [ ] 深色模式逐项通过（01 §10 D 段）
- [ ] 设计优化未破坏业务逻辑、架构与工程质量

## 16. 变更流程

本文是目标规范，任何改动**先改本文**：

| 想改什么 | 怎么做 |
| --- | --- |
| 改一项既有参数（色值、圆角、间距、字号、动画时长） | 先在本文对应表格改完并写理由 → 再改 `packages/design-tokens/tokens.json` → 重新生成两端常量 → 跑守门测试 → 过一遍深色模式 |
| 新增视觉元素（新卡片形态、新渐变、第三种图标轨、玻璃用法） | 先写清「解决什么问题 + 代价」，否则不写代码 |
| 改结构性关系（色板角色、圆角分档逻辑、密度分级、材质配比） | 等于换设计语言，需整篇重评，不能局部改 |

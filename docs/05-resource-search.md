# 05 · 资源整合搜索

> 唯一重点：**多个异构资源源怎么被抽象成一次搜索，怎么合并，怎么执行动作。**
> 不涉及：产品定位（[00](00-product-architecture.md)）、接口字段（[07](07-api-contract.md)）、
> 后端模块（[06](06-backend.md)）、视觉规范（[02](02-design-language.md) / [03](03-web-frontend.md)）。
>
> **本篇是骨架**：定抽象与语义，不定字段级实现。
> 本篇是**服务端内部设计**，客户端只消费 [07](07-api-contract.md) 定义的接口。

---

## 1. 要解决的问题

| 难点 | 表现 | 对策 |
| --- | --- | --- |
| 源异构 | PG 表结构、BitMagnet GraphQL、CloudSaver 脚本、semitio addon，返回结构完全不同 | provider 适配层 + 统一候选模型 |
| 源会失败 | 超时、限流、返回结构变了 | 超时预算 + 熔断 + **部分结果显式化** |
| 结果是两层 | 同一作品在多个源都有 | 作品 / 候选两层模型 |

---

## 2. Provider 抽象

### 2.1 契约

一个 provider 只需回答三件事：

| 方法 | 必需 | 说明 |
| --- | --- | --- |
| `search(query)` | 是 | 按查询返回候选 |
| `resolve(ref)` | 否 | 补全单个候选详情 |
| `transfer(ref, target)` | 否 | 执行落地动作 |

**只有 `search` 必须实现。** 其余能力缺失时，该源不支持对应动作，由能力声明决定 UI 是否显示按钮。

### 2.2 能力类型

`read_only`（只能搜）/ `direct`（可下载）/ `transfer`（可转存到 115）/ `push`（可推送）。

### 2.3 接入成本

新增一个源 = 一个实现类 + 一行注册 + 一条归一化规则。

**不引入框架、不做基类继承、不做生命周期管理。** provider 是普通对象，注册表持有。

### 2.4 启停

启停是配置项，不是代码改动。客户端可拉取「当前资源源列表 + 健康状态」用于渲染过滤条与降级提示。

---

## 3. 查询与候选模型（分层）

| 层 | 归属 | 内容 |
| --- | --- | --- |
| `SearchQuery` | 解析后 | 标题、年份、季、集、类型过滤、条数上限 |
| `RawCandidate` | provider 层产出 | 单源的一条原始结果，含大小、画质、来源类型、完整度、源特有信息 |
| `Candidate` | 归一化后 | 面向客户端的候选，带来源标识与**当前可执行动作** |
| `Work` | 合并后 | 作品层：标题、年份、季集、候选列表 |

**归一化要点**：源特有的信息（磁链、网盘链接、任务 ID）统一放进「源特有信息」字段，
不污染通用模型；但该字段会返回给客户端，**必须脱敏**（不得含 Cookie / Token）。

---

## 4. 合并与排序

### 4.1 合并

- 合并键：归一化标题 + 年份 + 季 + 集（归一化 = 去空格、去全角半角差、去常见副标题噪声后缀）。
- **年份缺失不参与区分**：宁可多列一项，也不要错合并 —— 错合并会隐藏掉正确的源。

### 4.2 排序

作品之间按匹配度（标题完全 > 包含 > 模糊），其次年份贴近度、候选数量。

候选之间按：动作可用性 → 画质 → 完整度 → 体积 → 来源稳定度。

**不做跨源热度加权** —— 不同源的种子数不可比，混排会制造虚假热度。

## 5. 失败、超时与部分结果

### 5.1 超时预算

一次搜索有**总预算**与**单源预算**（数值待实测确定）。所有源**并发**调用；
单源超预算即取消该源，总预算耗尽即取消剩余源。

串行必然超时 —— 并发是硬要求。

### 5.2 部分结果必须显式

搜索接口整体返回成功，但结果里带：

- `partial` 标志：任一源未成功返回即为真。
- 每个源的状态与耗时：成功 / 超时 / 错误 / 已熔断 / 已禁用。

**规则：`partial` 为真时，UI 必须显示「部分资源源未响应」。**
把「一个源挂了」呈现成「没搜到」属于契约违规。

### 5.3 熔断与恢复

单源连续失败到阈值即熔断，冷却后半开试探，成功则恢复。熔断中的源不出现在搜索请求里，
但在资源源列表中可见（标状态）。

### 5.4 缓存

按「源集合 + 查询词 + 年份 + 季集 + 类型过滤」做键，缓存**归一化后的候选**，
不缓存 provider 原始响应。写缓存不阻塞搜索。

## 6. 动作语义

| 动作 | 说明 | 依赖 |
| --- | --- | --- |
| 转存到 115 | **主路径**：文件落到 115，后续就是普通影视库条目 | 源需支持 transfer |
| 推送到网盘 | 源侧能力 | 源需支持 push |
| 下载到本地 | 源侧能力 | 源需支持 direct |

### 6.1 动作是异步任务

发起 → 返回动作 ID → 客户端轮询状态（待处理 / 执行中 / 成功 / 失败）。

| 要点 | 说明 |
| --- | --- |
| 不阻塞搜索 | 发起后立即返回，用户可继续操作 |
| 失败给可读原因 | 频控 / 目标目录不存在 / 源失效 / 未绑定 115 —— 不同原因对应不同下一步 |
| 源侧无进度就缺省 | **不要显示假进度条** |

### 6.2 动作前置校验

115 未绑定 → 提示去管理页绑定，**保持登录态**；目标目录不存在 → 引导重选；
源不支持该动作 → 不显示按钮；源已熔断 → 提示稍后重试或换源。

### 6.3 转存后的入库

转存成功 → 探测 → 刮削 → 写入影视库（异步）。

**转存成功 ≠ 立刻可播。** UI 先显示「已转存，正在整理」，入库完成后再出现「播放」。

## 8. 接入指南

1. 写一个 provider 实现类，实现 `search`。
2. 一行注册。
3. 补一条归一化规则（原始结果 → 候选）。
4. 填 §7 能力矩阵对应行。

**硬性要求**：

- `search` 内必须有超时保护，源挂起不能拖垮整体搜索。
- 原始响应中的凭据、Cookie 不得进入「源特有信息」。
- `search` 不得抛出未处理异常 —— 由搜索服务统一捕获并降级为「该源错误」。
- 标题清洗必须统一，否则合并键失效。
